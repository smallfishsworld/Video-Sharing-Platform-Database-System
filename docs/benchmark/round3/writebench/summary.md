# WriteBench, round 3

Generated by `python3 scripts/writebench/tables3.py` from the runs in this directory; each `<label>.json` holds the run's options, jar sha256, commit and boot, `<label>.log` its output and `<label>.deadlocks.txt` the deadlocks the server detected during the run (pg_stat_database). WriteBench and its modes are described in `scripts/writebench/WriteBench.java`; round 2's runs are in `docs/benchmark/round2/writebench`. From round 4 on, each JSON also records git HEAD and the porcelain status of the checkout and the SHA-256 and repository HEAD of every SQL file, taken inside the lock (`git_head`, `git_porcelain`, `sql_sha256`, `sql_git`); before, `code_sha` is the only commit, a label chosen by the caller.

Original = the 2023 implementation (the course submission on main); round 2 = this project at a330c0c (jar 42004a16); this version = the code named below. Every run holds `/home/user/work/bench.lock`; several runs share one hold (at most 15 minutes), with the original and this version alternating inside it. Steady runs use `--settle` (a `CHECKPOINT` after the import); deleteVideoWithViews deletes 8 imported videos (about 20,000 views each).

The runs of the first version of the round-3 fix (1717da9, whose co-view trigger scanned the whole co-view table on every deletion) are in `1717da9/`, summarized by `python3 scripts/writebench/tables3.py docs/benchmark/round3/writebench/1717da9`.
